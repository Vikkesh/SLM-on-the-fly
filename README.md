<h1 align="center">SAI — Sovereign Agentic Intelligence</h1>

<p align="center">An on-premise, air-gapped AI workbench for confidential industrial documents.<br>
Reads scans, photos and spreadsheets. Writes approval notes as Word, PDF or Excel. Nothing leaves the building.</p>

## Purpose

Refineries and public-sector plants produce inspection reports, permits and readings that cannot be
sent to a cloud model. SAI runs two open-weight models on a local server and an agentic pipeline on
the operator's laptop, so an engineer can drop in a scanned inspection report and get back a signed-off
approval note — with every byte staying on the LAN.

- **Automatic routing** — each request goes to the model suited to it: a *reader* for images, a *writer* for text and documents. The routing is shown on every answer.
- **Real deliverables** — `.docx`, `.pdf` and `.xlsx` files generated by tools, not text pasted into a chat.
- **Provably offline** — the only network traffic is model inference to the server laptop; tools, files and sessions are local.

## How it fits together

```
 MODEL SERVER (laptop A)                   OPERATOR (laptop B, one per user)
 ┌────────────────────────┐                ┌──────────────────────────────────────────────┐
 │ Ollama                 │                │  browser ──▶ SAI dispatcher :8080             │
 │  qwen2.5vl:7b  reader  │ ◀── LAN only ──┤       normalize files · route · add context   │
 │  qwen3:8b      writer  │   (inference)  │            │                                  │
 │                        │                │       SAI agent engine :8790                  │
 └────────────────────────┘                │        Reader agent      Writer agent         │
                                           │            │                  │  tool calls   │
                                           │       document tools :9000  ──┘               │
                                           │        OCR · Word · PDF · Excel               │
                                           │                                               │
                                           │       output/  ← generated documents          │
                                           └──────────────────────────────────────────────┘
```

```
 scan.pdf + "draft the approval note"
      │
      ▼
 normalize      pdf → png (or xlsx → table, docx → text)      the models only ever see text and images
      │
      ▼
 Reader         transcribes the scan, lists findings          qwen2.5vl:7b
      │
      ▼
 context        keyword match against local SOP excerpts      no vector DB, no embeddings
      │
      ▼
 Writer         drafts the note, calls generate_docx          qwen3:8b
      │
      ▼
 output/approval-note.docx   +   "Routed to: Reader → Writer"  on screen, with timings
```

## Run it

```bash
cd sovereign
scripts/run_all.sh prepare                                     # once, with internet: node, venv, engine, samples
scripts/run_all.sh start --ollama http://<model-laptop>:11434 --model qwen3:8b --vision-model qwen2.5vl:7b
```

Open **http://127.0.0.1:8080**. Try the starter actions on the empty screen — they attach the sample
scan and spreadsheet in `sovereign/samples/`. `restart` reloads after a code change, `stop` shuts down.

If the server has a single text-only model, images are read with local OCR instead and the routing
track says so.

## Repository

```
sovereign/            everything SAI adds
  dispatcher/           router, file normalization, context lookup, streaming UI
  mcp_server/           document tools: extract_from_scan, generate_docx, generate_pdf, generate_xlsx
  skills/               the approval-note procedure the writer follows
  context/              SOP and manual excerpts used for context
  scripts/              prepare / start / restart / stop, model server setup
ARCHITECTURE_sovereign_ai_workbench.md    full design, per-flow diagrams, setup order
PRD_sovereign_ai_workbench_v2.md          scope, decisions, acceptance criteria
```

The agent engine (sessions, tool calling, sandbox) lives under `packages/` and is used as-is through
its HTTP API; SAI does not modify it.
